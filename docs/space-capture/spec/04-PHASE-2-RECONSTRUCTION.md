# فاز دو — موتور بازسازی سه‌بعدی

## هدف
تبدیل capture تأییدشده به صحنه Gaussian Splat به همراه metadata و assetهای مورد نیاز Viewer.

## مراحل pipeline

1. دریافت job و قفل idempotent.
2. دانلود فایل از Object Storage به فضای موقت worker.
3. بررسی مجدد فایل و استخراج metadata.
4. استخراج فریم با FFmpeg؛ نرخ نمونه‌برداری ثابت و قابل تنظیم باشد، نه استخراج کورکورانه تمام فریم‌ها.
5. حذف فریم‌های تار، تکراری یا کم‌اطلاعات با معیارهای قابل اندازه‌گیری.
6. اجرای COLMAP/SfM برای camera poses و sparse reconstruction.
7. بررسی تعداد فریم‌های ثبت‌شده و کیفیت camera alignment.
8. اجرای Nerfstudio/Splatfacto با تنظیمات versioned.
9. ذخیره checkpoint و logهای لازم برای عیب‌یابی.
10. تبدیل خروجی به فرمت سازگار با Viewer انتخابی.
11. تولید preview، thumbnail، metadata و quality report.
12. ساخت collision mesh اولیه یا علامت‌گذاری نیاز به اصلاح دستی.
13. بارگذاری assetها به Object Storage.
14. ثبت وضعیت `review` و اطلاع به پنل مدیر.
15. پاک‌سازی امن فایل‌های موقت طبق retention.

## طراحی worker

- GPU worker از API جدا باشد.
- هر job در محیط ایزوله و با محدودیت CPU/RAM/VRAM اجرا شود.
- job دارای heartbeat، timeout و retry محدود باشد.
- خطای قابل بازیابی از خطای دائمی تفکیک شود.
- لاگ فنی برای اپراتور و پیام ساده برای مدیر کافه جدا باشند.
- jobهای یک capture به‌صورت هم‌زمان چند بار اجرا نشوند.
- worker نسخه pipeline و پارامترها را ثبت کند.

## کیفیت و تشخیص شکست

موارد زیر بررسی شوند:
- درصد فریم‌های register شده
- تعداد و پراکندگی camera poses
- کیفیت پوشش فضای ورودی
- اندازه فایل و تعداد splatها
- وجود artifactهای شدید
- کامل بودن preview
- قابل باز شدن بودن asset در Viewer
- میزان پوشش collision mesh در نواحی قابل حرکت

thresholdها بعد از POC تعیین شوند؛ عدد ثابت و حدسی در کد hardcode نشود.

## خروجی asset

حداقل:
- فایل خام/مرجع splat
- فایل بهینه‌شده برای Viewer
- thumbnail و preview
- metadata شامل ابعاد تقریبی، transform و نسخه pipeline
- collision mesh یا وضعیت نیازمند اصلاح
- گزارش کیفیت

## اصلاح انسانی

در MVP، مدیر یا اپراتور باید بتواند:
- preview را بررسی کند
- در صورت کیفیت نامناسب capture مجدد بخواهد
- موقعیت اولیه دوربین و نقاط ورود را تنظیم کند
- نسخه را تأیید یا رد کند

ویرایش mesh کامل و ابزار حرفه‌ای Blender جزو الزام MVP نیست.

## تست‌ها

- job موفق
- crash در میانه آموزش
- retry پس از crash
- کمبود فضای دیسک
- کمبود VRAM
- فایل ورودی نامناسب
- اجرای هم‌زمان jobهای چند کافه
- عدم دسترسی worker به داده tenant دیگر
- اطمینان از عدم تغییر رزرو و API اصلی

## معیار پذیرش

یک capture معتبر به نسخه قابل بررسی تبدیل شود؛ خطاها قابل مشاهده باشند؛ jobها پس از restart قابل بازیابی باشند؛ و خروجی در Viewer فاز سه باز شود.
