# فاز صفر — Proof of Concept

## هدف

پیش از توسعه محصول، با یک ویدئوی واقعی ثابت کنیم که می‌توانیم:
1. از ویدئو یک صحنه Gaussian Splat قابل مشاهده بسازیم.
2. خروجی را در مرورگر نمایش دهیم.
3. حرکت دوربین در حد MVP قابل قبول باشد.
4. محدودیت کیفیت و هزینه را اندازه‌گیری کنیم.

این فاز نباید به دیتابیس production یا رزرو متصل شود.

## ورودی آزمایشی

یک ویدئو از یک فضای واقعی، ترجیحاً بدون افراد متحرک:
- 4K مطلوب؛ حداقل 1080p
- 30fps ترجیحی
- بدون زوم دیجیتال
- نور ثابت
- حرکت آرام و پیوسته
- مسیر دارای هم‌پوشانی تصویری
- پوشش تمام نقاط، نه فقط چرخش در یک محل

ویدئوی فعلی کاربر با مشخصات 512×910، 30fps و حدود 53 ثانیه فقط برای ارزیابی اولیه حرکت و پوشش مناسب است؛ برای قضاوت نهایی درباره کیفیت بازسازی، نمونه‌ای با رزولوشن بالاتر ضبط شود.

## وظایف

### 1. ثبت مشخصات محیط
- سیستم‌عامل و GPU worker
- مدل GPU و VRAM
- نسخه CUDA/driver در صورت استفاده
- نسخه Python و ابزارهای بازسازی
- فضای دیسک و زمان اجرا

### 2. بررسی ورودی
- خواندن metadata با FFprobe
- استخراج چند فریم نمونه
- بررسی blur، نور، تکراری بودن و پوشش
- ثبت گزارش قابل فهم

### 3. پایپ‌لاین دستی اولیه
- استخراج فریم با FFmpeg
- اجرای COLMAP یا مسیر SfM سازگار با نسخه Nerfstudio
- آموزش Splatfacto
- خروجی splat
- باز کردن در Viewer منتخب

### 4. آزمون Viewer
- بارگذاری روی دسکتاپ
- بارگذاری روی یک iPhone واقعی
- کنترل حرکت و جهت دوربین
- بررسی artifact، سوراخ‌های تصویر، ghosting و نقاط شناور
- اندازه‌گیری زمان بارگذاری و حافظه

### 5. آزمون collision
برای POC یک collision ساده و دستی کف/دیوار کافی است. هدف این نیست که در فاز صفر mesh دقیق کل کافه تولید شود؛ هدف اثبات امکان حرکت کنترل‌شده است.

## خروجی‌های الزامی

- ویدئوی ورودی و گزارش مشخصات
- فریم‌های استخراج‌شده منتخب
- تنظیمات و نسخه ابزارها
- مدل/فایل Splat خام و نسخه قابل نمایش
- لینک یا build محلی Viewer
- گزارش زمان پردازش و هزینه GPU
- گزارش عملکرد موبایل
- فهرست محدودیت‌ها و تصمیم Go/No-Go

## معیار پذیرش

- صحنه در Viewer بدون خطای بحرانی باز شود.
- بخش اصلی فضای ضبط‌شده از چند زاویه قابل مشاهده باشد.
- روی یک موبایل واقعی تست شود.
- حرکت کاربر به شکل کنترل‌شده قابل استفاده باشد.
- زمان پردازش و هزینه اندازه‌گیری شده باشد.
- راهکار قابل تکرار باشد؛ نه فقط یک اجرای دستی غیرقابل بازتولید.

## معیار توقف

اگر ویدئوی ورودی باعث بازسازی ناقص شد، قبل از تغییر معماری، کیفیت فیلم‌برداری و دستورالعمل capture اصلاح شود. اگر Viewer انتخابی روی موبایل پایدار نیست، گزینه جایگزین ارزیابی شود. تا عبور فاز صفر، فازهای بعدی توسعه production شروع نشوند.
