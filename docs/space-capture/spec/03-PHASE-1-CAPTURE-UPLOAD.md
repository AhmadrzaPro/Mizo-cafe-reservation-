# فاز یک — ضبط، آپلود و اعتبارسنجی ویدئو

## هدف
ساخت تجربه ساده برای مدیر کافه تا ویدئوی مناسب بازسازی را ضبط و امن آپلود کند.

## تجربه کاربری

1. مدیر از پنل شعبه گزینه «ساخت فضای سه‌بعدی» را می‌زند.
2. راهنمای ضبط شامل نمونه مسیر، نکات نور و حرکت نمایش داده می‌شود.
3. مدیر ویدئو را انتخاب یا ضبط می‌کند.
4. پیش از آپلود، metadata و حجم فایل نمایش داده می‌شود.
5. فایل با signed URL به Object Storage آپلود می‌شود.
6. کلاینت پایان آپلود را اعلام می‌کند.
7. سرور فایل را بررسی و گزارش کیفیت تولید می‌کند.
8. فقط در صورت عبور از validation، دکمه «شروع بازسازی» فعال می‌شود.

## راهنمای capture داخل محصول

- لنز اصلی موبایل و بدون زوم دیجیتال
- حرکت آهسته و پیوسته
- دوربین در ارتفاع نسبتاً ثابت
- حرکت در امتداد دیوارها و بین مبلمان با هم‌پوشانی دید
- ثبت گوشه‌ها و فضاهای متصل
- پرهیز از چرخش سریع و تغییر ناگهانی نور
- در صورت امکان محیط بدون مشتری و افراد متحرک باشد
- فضاهای جدا مانند تراس در capture مستقل ثبت شوند، سپس در پنل به همان شعبه متصل شوند

## اعتبارسنجی سمت سرور

- container و codec واقعی با FFprobe بررسی شود.
- MIME اعلامی کلاینت قابل اعتماد نباشد.
- سقف حجم، مدت و رزولوشن configurable باشد.
- رزولوشن پایین‌تر از حد MVP هشدار یا رد قابل تنظیم داشته باشد.
- فایل خراب، خالی یا غیرقابل decode رد شود.
- checksum ثبت شود.
- فایل در مسیر tenant-scoped ذخیره شود.
- در صورت شکست آپلود، امکان ادامه یا شروع مجدد امن فراهم شود.

## API و مدل داده

از قراردادهای `scene_captures` و endpointهای سند معماری استفاده شود. upload URL باید محدود به object key و زمان مشخص باشد. API اصلی نباید بایت‌های ویدئو را از داخل سرور خود عبور دهد، مگر زیرساخت فعلی الزام کند.

- ویدئوی سالم و خراب

- تلاش کاربر کافه A برای دسترسی به capture کافه B
- آپلود تکراری و اعلام complete چندباره
- موبایل و دسکتاپ

## معیار پذیرش

- آپلود resumable یا retry-safe باشد.
- هیچ فایل private بدون مجوز عمومی نشود.
- گزارش validation قابل فهم باشد.
- مدیر بتواند capture نامعتبر را جایگزین کند.
- هیچ تغییری در جریان رزرو فعلی ایجاد نشود.
