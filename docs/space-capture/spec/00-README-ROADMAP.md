# Mizo AI Space Capture
## بسته اسناد معماری و اجرای قابلیت بازسازی سه‌بعدی کافه از ویدئو

**هدف محصول:** مدیر کافه با موبایل از محیط فیلم می‌گیرد؛ Mizo ویدئو را پردازش می‌کند؛ محیطی فوتورئالیستی و قابل گردش در مرورگر منتشر می‌شود؛ میزها به‌صورت داده مستقل روی صحنه قرار می‌گیرند و رزرو از سیستم اصلی Mizo انجام می‌شود.

## تصمیم‌های معماری قطعی

1. خروجی بصری اصلی: 3D Gaussian Splatting (3DGS).
2. خروجی مکمل: هندسه سبک برای کف، دیوارها، موانع و collision؛ در صورت نیاز با ابزارهای کمکی و اصلاح انسانی.
3. اطلاعات میز، منطقه و رزرو هرگز داخل فایل Splat منبع حقیقت نیستند؛ در دیتابیس Mizo نگهداری می‌شوند.
4. پردازش ویدئو و آموزش GPU در سرویس مستقل و صف‌محور اجرا می‌شود؛ API اصلی رزرو نباید منتظر پردازش بماند.
5. انتشار صحنه فقط پس از کنترل کیفیت و تأیید مدیر کافه انجام می‌شود.
6. هر صحنه و هر asset باید به cafe_id و در صورت نیاز branch_id محدود باشد.
7. برای MVP از GPU ابری ساعتی/درخواستی استفاده شود؛ خرید سرور GPU دائمی به بعد از اندازه‌گیری هزینه موکول شود.

## مسیر پیشنهادی MVP

- ویدئوی ورودی → اعتبارسنجی → استخراج فریم → COLMAP/SfM → آموزش 3DGS با Nerfstudio/Splatfacto → بهینه‌سازی → Viewer وب → ثبت موقعیت میزها → رزرو از API فعلی.
- برای نمایش وب، ابتدا PlayCanvas و SuperSplat Viewer را در یک نمونه مستقل ارزیابی کنید. قبل از انتخاب نهایی، مجوز، فرمت خروجی، سازگاری موبایل، کنترل دوربین و API تعبیه/سفارشی‌سازی را بررسی کنید.
- Blender ابزار اجباری در مسیر خودکار MVP نیست. فقط برای اصلاح دستی mesh/asset یا ساخت نمونه نمایشی به‌کار رود.

## ترتیب اجرای اجباری

فازها را به ترتیب اجرا کنید. فاز بعدی فقط پس از پاس‌شدن معیارهای پذیرش فاز قبلی شروع شود. در MVP از بازنویسی معماری فعلی Mizo، تغییر سیستم رزرو، یا انتقال دیتابیس خودداری شود.

## دستورالعمل برای عامل کدنویس

قبل از هر تغییر:
1. مخزن فعلی را بررسی و ساختار واقعی frontend/backend/database را مستند کند.
2. فایل‌های موجود، قرارداد APIها، سیستم احراز هویت، tenancy و رزرو را شناسایی کند.
3. طرح ادغام را پیشنهاد دهد و فایل‌های فعلی را بدون نیاز تغییر ندهد.
4. هیچ تکنولوژی یا سرویس خارجی را با فرض وجود آن نصب یا فعال نکند.
5. هر فاز را در branch مستقل پیاده‌سازی کند، تست‌ها را اجرا کند و گزارش تغییرات ارائه دهد.
6. secret، کلید ذخیره‌سازی یا credential را در کد یا لاگ قرار ندهد.
